# 园区碳观察技术设计

## 1. 设计目标

项目不是一次性大屏，而是一套可以公开托管、周期更新、保留版本、自动报告并执行可行性初筛的数据产品。公开页面尽量简洁，后台保留来源健康、内容哈希、证据边界和计算过程。

## 2. 总体结构

```text
公开来源与园区填报
        ↓
采集与来源健康
        ↓
URL规范化、去重、版本化档案
        ↓
园区实体映射与证据分层
        ↓
统计分析、五问工作台、可行性计算
        ↓
日报、周报、可行性报告
        ↓
质量门禁
        ↓
GitHub Pages公开发布
```

### 2.1 数据层

- `data/park_catalog.csv`：园区主表；
- `data/archive.jsonl`：滚动公开档案；
- `data/source_health.json`：来源健康；
- `data/required_data_fields.csv`：园区数据准备字段；
- `data/standard_rules.csv`：政策、指标和核算规则；
- `data/technology_guidance.csv`：减排设施指南；
- `data/assessments/*.json`：可行性场景。

### 2.2 处理层

- `collector.py`：公开来源发现、正文摘要、主题分类和失败隔离；
- `archive.py`：规范 URL 合并、内容哈希和滚动上限；
- `analytics.py`：园区、来源、主题和证据漏斗统计；
- `accounting.py`：数据门槛、排放清单和国家指标差距；
- `portfolio.py`：项目经济性和预算约束组合；
- `feasibility.py`：五问结果、措施筛选和风险；
- `reports.py`：日报、周报和可行性报告；
- `exporter.py`：静态网站导出；
- `validator.py`：发布前质量检查。

### 2.3 展示层

网站使用原生 HTML、CSS 和 JavaScript，不依赖外部前端框架或长期运行的服务器。构建后输出到 `site/`，可部署到 GitHub Pages、Cloudflare Pages、Netlify 或普通静态服务器。

## 3. 自动更新

`.github/workflows/pages.yml` 在以下情况运行：

- 推送到 `main`；
- 每 6 小时定时检查；
- 手动触发。

工作流依次执行初始化、公开来源同步、单元测试、网站构建、页面验证、动态数据回写和 Pages 发布。质量门禁失败时不部署本次产物，因此上一版成功网站保持可用。

### 3.1 来源健康

单个来源失败不会阻断其他来源。来源状态规则：

- 连续失败 1—2 次：`failed`；
- 连续失败 3—6 次：`watch`；
- 连续失败 7 次：`quarantined`；
- 隔离 7 天后自动复测。

### 3.2 档案合并

一条规范化 URL 对应一条主记录。处理包括：

- HTTP 升级为 HTTPS；
- 域名小写；
- 去除片段和常见跟踪参数；
- 保留有业务意义的查询参数；
- 内容变化时增加版本计数；
- 保存前一内容哈希；
- 最多保留 100000 条。

## 4. 数据门槛

正式核算必须确认：

1. 园区标准名称；
2. 核算边界；
3. 纳入企业清单；
4. 基准年；
5. 综合能源消费；
6. 范围一排放；
7. 范围二排放；
8. 工业过程排放。

范围一、范围二和过程排放可以为零，但必须明确提供。门槛未通过时，只输出资料画像、措施指南和补数任务。

## 5. 核算与差距

排放初筛采用：

```text
园区净排放 = 范围一 + 范围二 + 工业过程排放 − 经核验移除量
单位能耗碳排放 = 园区净排放 / 综合能源消费量
```

同时计算清洁能源消费占比、产品单位能耗、工业固废综合利用率、余热余冷余压综合利用率和工业用水重复利用率。阈值从规则表读取，正式使用前应核验政策版本和园区适用条件。

## 6. 项目可行性与组合优化

### 6.1 单项目经济性

```text
年度净收益 = 年度节省 − 年度运维
净现值成本 = 初始投资 − 年度净收益 × 年金现值系数
生命周期减排 = 年度减排 × 寿命
边际减排成本 = 净现值成本 / 生命周期减排
简单回收期 = 初始投资 / 年度净收益
```

### 6.2 组合选择

在预算约束下：

- 若存在满足年度减排目标的组合，选择净现值成本最低者；
- 若不存在满足目标的组合，选择年度减排量最大者；
- 同等情况下依次比较投资、减排量和项目数量；
- 支持前置项目和互斥组；
- 最多对 24 个项目执行精确搜索。

### 6.3 风险输出

至少检查：

- 数据与边界；
- 绿电和电网条件；
- 项目参数证据；
- 年度减排目标缺口；
- 国家指标差距。

结果属于前期筛查，不替代专项可研。

## 7. 页面交互与离线能力

- 所有可见按钮均绑定跳转、筛选、计算、导入或导出；
- 不使用装饰性空按钮；
- 站内数据通过静态 JSON 加载；
- Service Worker 缓存核心文件；
- `?selftest=1` 可执行浏览器端基础自检；
- GitHub Issues 用于公开数据修订和计算问题留痕。

## 8. 质量门禁

发布前检查：

- 必需文件存在；
- 数据文件可解析；
- 园区和动态不为空；
- 本地链接有效；
- 关键交互钩子存在；
- 可见按钮有操作标识；
- 单元测试通过；
- JavaScript 语法通过。

## 9. 安全与合规

- 只访问正常公开页面；
- 不绕过登录、验证码、付费墙、限流或其他技术措施；
- 不在仓库保存企业敏感台账；
- 第三方内容只保存链接、必要元数据和短摘要；
- 密钥只应存放在 GitHub Secrets；
- 所有正式结论应回到原始材料核验。
