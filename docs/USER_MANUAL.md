# 园区碳观察用户说明手册

## 1. 网站用途

园区碳观察面向经济技术开发区、产业园区及园中园，用公开资料和园区填报数据回答五个实际问题：

1. 数据够不够；
2. 现状是什么；
3. 差距在哪里；
4. 怎么减；
5. 花多少钱。

网站中的公开记录用于发现政策、园区实践、设施线索和待核验数字。只有同一园区边界、同一年度、同一单位且能够追溯到原始台账的数据，才进入正式核算。园区建设名单、新闻报道和市级统计数据不能直接替代园区绩效数据。

## 2. 进入网站

### 公开网站

仓库发布到 GitHub Pages 后，访问 Pages 地址即可。网站由定时工作流自动更新，不需要长期运行服务器。

### 本地查看

Windows 双击 `run.bat`，或在 PowerShell 中运行：

```powershell
.\run.ps1 serve
```

macOS 或 Linux：

```bash
./run.sh serve
```

默认地址为 `http://127.0.0.1:8765`。

## 3. 园区现场

地图包含全国园区、国家级建设名单、广东专题和国际参考案例。点击点位后，可查看：

- 园区名称、地区和建设层级；
- 产业类型、建设周期和边界模式；
- 已关联的公开事实；
- 事实的来源、日期和限制说明；
- 当前仍需补充的数据。

地图点位用于导航，不等同于园区法定四至。正式工作应补充批复边界图、GIS 文件或坐标多边形。

## 4. 今日动态与资料库

“今日动态”展示最新政策、园区建设和设施实践；“资料库”可同时检索园区名录、动态档案、政策标准和减排措施。

每条动态至少保留标题、日期、来源、摘要、主题和原文入口。摘要只用于快速定位，重要数字和实施条件应回到原文核验。来源连续失败时会进入观察或隔离，但既有档案不会被删除。

## 5. 五问工作台

### 5.1 数据够不够

逐项勾选已经取得的材料，系统计算数据准备度。点击“生成补数任务”后，缺失字段会转化为任务，包含：

- 字段名称；
- 优先级；
- 责任部门；
- 最低材料；
- 建议时限。

任务可以导出为 CSV，直接用于园区调研和部门分工。

### 5.2 现状是什么

选择园区后，可从管委会、园区企业、能源运营、公共设施、监管评估和研究评估六个视角查看资料画像。系统还会根据产业、建设层级、边界模式、地区和建设周期寻找结构相近园区。

结构相似只回答“哪些园区值得调研”，不等同于零碳绩效排名。

### 5.3 差距在哪里

先确认边界和自然年，再录入综合能源消费、范围一、范围二、工业过程排放及引导指标。系统计算：

- 园区净排放；
- 单位能耗碳排放；
- 核心指标目标值；
- 清洁能源、固废利用、余热余压利用和工业用水重复利用等差距；
- 达到核心阈值所需的年度减排量。

没有通过数据门槛时，系统不输出达标结论。

### 5.4 怎么减

措施库分为：

- **无悔型**：计量、能碳管理、设备效率、空压、蒸汽、余热、水循环、维护和工业协同等；
- **条件型**：分布式光伏、绿电直连、储能、微电网、热泵、电锅炉等；
- **战略型**：深度工艺改造、燃料和原料替代、产业结构调整等。

绿电直连不是默认第一步。进入专项可研前，应确认源荷匹配、网架安全、直接消纳、计量结算、项目主体、交易责任和环境属性归属。

### 5.5 花多少钱

项目表至少需要：投资、年度减排、年度节省、年度运维、寿命、实施年和参数证据。点击“运行可行性分析”后，系统在预算和目标约束下形成项目组合，并给出：

- 入选项目和组合投资；
- 年度减排与目标缺口；
- 年度净收益、简单回收期和边际减排成本；
- 利益相关方分工；
- 分年度实施路径；
- 数据、技术、经济和实施风险；
- Markdown 可行性初筛报告。

网页最多对 20 个项目进行精确穷举；命令行模块使用带剪枝的精确搜索，可处理最多 24 个候选项目。

## 6. 自动报告

每次构建会生成：

- 最新日报：当天或最近公开记录；
- 最新周报：最近 7 天主题、来源和重点记录；
- 可行性初筛报告：示范或用户提供场景的五问分析。

报告同时提供 HTML、Markdown 和 JSON，便于阅读、二次编辑和系统调用。

## 7. 数据更新

默认工作流每 6 小时检查一次公开来源。处理流程为：

1. 读取来源配置；
2. 发现与园区建设相关的公开页面；
3. 规范 URL、去除跟踪参数并去重；
4. 保存内容哈希、首次归档时间和最近检查时间；
5. 更新来源健康；
6. 生成统计、日报、周报和可行性报告；
7. 通过质量检查后发布网站；
8. 将滚动档案和来源健康提交回仓库。

定时任务属于周期性更新，不是秒级数据流。公开政策和园区信息以日、周为主，每 6 小时检查用于缩短发现延迟。

## 8. 数据更正与来源补充

<a id="data-correction"></a>

公开网站底部的“提交数据更正”会进入 GitHub Issues。建议分别使用：

- 数据更正；
- 新来源建议；
- 计算问题；
- 可行性结果反馈。

提交时应提供对象、原文入口、发布日期、建议修改内容和核验理由。不要在公开 Issue 中上传企业敏感台账、个人信息、合同价格或其他非公开材料。

## 9. 正式使用边界

本网站提供前期筛查、公开信息追踪、数据准备、标准差距和项目排序，不替代：

- 法定碳排放核查；
- 节能审查；
- 环境影响评价；
- 电网接入系统审查；
- 工程可行性研究；
- 设备选型和施工图设计；
- 投融资决策。
